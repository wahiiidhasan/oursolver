# OurSolver editorial and SEO plan

## Positioning

OurSolver helps visitors solve image and PDF file problems on their own device. Use the brand naturally; target specific file tasks before the broad word “solver”. Search-volume and keyword-difficulty estimates have not been purchased or verified, and rankings cannot be guaranteed.

The six launch guides are complete practical articles, around 400 words each. Expand only where extra examples answer real questions. There is no required SEO word count. Do not change publication dates just to make an unchanged article look fresh. Use each article’s `published` and `modified` fields (YYYY-MM-DD) to preserve its own history.

## Reusable writing prompt

Write an original OurSolver guide answering the supplied file-processing question. Begin with the direct answer and a specific everyday situation. Explain the relevant file concepts in plain English. Include one worked example with explicit dimensions, file sizes or page numbers, a short step-by-step workflow matching the actual tool, common failure cases, and a verification checklist. Link to the relevant existing OurSolver tool and one closely related guide using descriptive anchors. Use natural phrasing, varied sentence lengths and useful headings. Write to the depth needed, usually 500–900 words for a substantial tutorial, without padding to hit a count. Supply a unique title, lowercase hyphenated slug, concise description and clean semantic HTML body. Verify software-specific or changing claims from primary documentation and cite those sources. Do not invent testing, quotes, credentials, user statistics, or rankings. Do not promise a file-size target, lossless compression, intact PDF signatures or universal compatibility. Keep advice within OurSolver's implemented features. Do not insert scripts, inline event handlers or untrusted HTML.

## Six next-article briefs

1. **Why does my image get larger after conversion?** Explain that codec, quality and content matter; conversion alone is not compression. Compare a flat illustration with a textured photo. Link to Convert image and Compress image.
2. **1200 × 630 images: fit, stretch or crop?** Show the aspect-ratio calculation. Explain that this launch tool offers fit and stretch, not cropping. Do not imply a fitting image fills the requested rectangle.
3. **Why does a transparent PNG turn white as a JPG?** Explain the lack of an alpha channel in JPG and this tool's white fill. Demonstrate when PNG or WebP is appropriate.
4. **How to remove one page from a PDF without changing the original.** Use a six-page example selecting 1-2,4-6. Explain page numbering and checking the output.
5. **Why do PDF forms stop working after merging?** Explain page content versus document-level features. State the tool's limits and when to use the original authoring application.
6. **How to put phone photos in the right PDF order.** Explain selecting, reordering and checking portrait pages; discuss A4, Letter and image-sized pages without claiming OCR.

## Publishing checks

Read the draft aloud, remove repetition, reproduce its example with sample files, verify every link, check the title matches the intent, add descriptive image alt text if needed, and run the build and audit. Articles should remain accurate if a visitor opens the tool immediately afterward.

Keep expansion related to file problems, documents and creator workflows. Do not publish unrelated trend articles merely for raw traffic. Build one useful original page for each distinct need rather than many nearly identical target-size pages.

## Growth after launch

Start with Search Console impressions and queries once data appears. Improve pages that earn impressions but poorly answer the query. Record download completion and errors only if privacy-conscious measurement is intentionally added. Revisit whether batch image processing is worth building based on real usage and feedback. Monetization and recurring-visitor potential remain hypotheses to validate.
